# quote_page_check

Маленькая проверка для моего диссертационного помощника. Карточка статьи не должна считаться готовой, если цитата не находится на той странице, которую я указал.

Модуль не читает PDF и не вызывает модель. На вход уже извлечённый текст страницы и строка цитаты. Так его можно гонять в тестах без датасета и без ключа к API.

## Запуск

Из этой папки:

```
python run.py
```

Откроется страница в браузере. Слева текст страницы и её номер, справа цитата. Можно открыть `.txt` или нажать Ctrl+Enter. Кнопка «Проверить» даёт один из трёх статусов: цитата нашлась, на странице её нет, поле пустое. Три кнопки справа подставляют учебный абзац.

Тот же экран из Docker, если не хочется ставить Python:

```
docker compose up --build
```

Страница: http://127.0.0.1:8765/

Тесты:

```
pip install -r requirements.txt
pytest
```

Тот же разбор можно вызвать из консоли, если текст уже лежит в файле:

```
python -m quote_check page.txt 3 "фрагмент цитаты"
```

Код возврата 0, если цитата нашлась. 1, если нет или строка пустая. Без аргументов `python -m quote_check` открывает ту же страницу, но тогда нужен `PYTHONPATH=src`. `python run.py` этого не требует.

## Что считаю найденным

Пробелы, переводы строки и регистр схлопываются. Фраза может быть разорвана в PDF по строкам, и проверка всё равно её увидит, если куски идут подряд.

Пустая цитата не проходит. Иначе можно закрыть поле, ничего не вставив.

## Чего нет

- Перенос слова с дефисом на следующую строку (`мет-` / `рики`) я не склеиваю. Это отдельный случай, его легко сломать на настоящих дефисах.
- Цитата, которая начинается внизу одной страницы и заканчивается на следующей, тоже мимо: функция смотрит одну страницу.

Оба пункта открыты как issues: https://github.com/Armani7777/applied_software_development_project/issues/1 и https://github.com/Armani7777/applied_software_development_project/issues/2. Шаблон лежит в `.github/ISSUE_TEMPLATE`.

## CI

Файл `.github/workflows/ci.yml`. На push и на pull request два шага. Сначала pytest на Python 3.12. Потом сборка образа, pytest внутри контейнера и проверка, что страница на порту 8765 отвечает.

`Jenkinsfile` — те же три шага для локального Jenkins. Поднять сервер: `docker compose -f jenkins/docker-compose.yml up -d`, открыть http://localhost:8080, создать Pipeline и указать этот репозиторий. Образ в Docker Hub я не пушу: отдельный аккаунт ради учебной проверки не завёл.

Деплоя в Kubernetes нет. Один процесс на одном порту, оркестратор здесь нечего масштабировать.

Ветка одна, `main`.
